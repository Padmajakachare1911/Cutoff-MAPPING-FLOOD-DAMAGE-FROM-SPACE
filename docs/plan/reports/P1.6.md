# P1.6 — Sentinel-2 evidence stage

## What was built
- `src/cutoff/data/sentinelhub.py`: `fetch_s2_best(grid, around, days, cfg, after=None, ...)`.
  1. Lists `sentinel-2-l2a` STAC items within ±`days` of the S1 post scene and groups them by UTC date.
  2. For each date, fetches a cheap **20 m SCL probe** (`SCL`, `dataMask`, UINT8) through the Process API and counts
     clear AOI pixels.
  3. Picks the date with the most clear pixels (tie → closest to the S1 post).
  4. Fetches **B03, B11, SCL, dataMask** on the 10 m grid (FLOAT32 reflectance, no manual offset;
     `mosaickingOrder: leastCC`). The response is checked against the grid as in P1.3, and processing units are logged.
  5. Returns `(array, "<item ids of the chosen date>")`, or `None` when there are no candidates.
- `src/cutoff/data/s2.py`
  - `s2_layers(...)`: clear = SCL ∈ {4, 5, 6, 7} (`s2.clear_scl`, snow 11 excluded, D11); water = clear & MNDWI > 0
    (`s2.mndwi_threshold`); both layers are 255 outside the data mask. A zero denominator is never water.
  - `stage_s2(ctx)` reads the S1 post time from `pairs.json`, writes `s2_water.tif` / `s2_clear.tif`, and returns
    `{"s2_scenes", "s2_clear_fraction"}`.
  - **It never raises.** No candidate, or best clear fraction < `s2.min_clear_fraction` (0.10) →
    `{"s2_scenes": [], "s2_clear_fraction": None}` + `ctx.warn("Sentinel-2: no clear scene within ±5 days")`. Any
    error (credentials, network, missing `pairs.json`, empty cache in cached mode) → the same empty return plus a
    `Sentinel-2 skipped: ...` warning.
  - Cache: `cache/s2/<grid_hash>/<post_id>.tif|.json` (a "no scene" result is cached too). `cached` mode reads only
    the cache.

## Deviation (flagged for review): S2 dates must also be after the event
The plan's window is "±5 days of the S1 post scene". For Trishuli that window includes **08-24, before the event**
(08-26 02:52), and 08-24 is the clearest date (39 % cloud). A pre-event optical scene shows no flood. Through the
gating rule "class 1 and S2 clear-no-water → class 2" it would demote real flood pixels, and its water would be
pre-event water. Following D4 (post evidence strictly after the event), candidates are restricted to the ±5 d window
**and** after `ctx.event_datetime` (`after=` argument). Nothing else changes. If the team wants the literal window, set
`s2.require_after_event: false` in `configs/default.yaml` (added 2026-10-13, default `true`; the S2 cache is
keyed on it). See `P1_UPDATES_LOG.md` U1.
