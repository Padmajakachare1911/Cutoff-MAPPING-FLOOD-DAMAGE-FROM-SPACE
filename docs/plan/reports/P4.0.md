# P4.0 - codebase analysis and setup

## What the project does

Cutoff maps post-event flood/debris evidence, intersects pre-event infrastructure,
and estimates road access under three closure assumptions. It is an educational
prototype. Exposure does not establish physical damage; unknown access is unmapped.

## Codebase and workflow

- P1 `data/` selects same-track S1 with sufficient coverage, caches raw calibrated
  arrays, applies Lee Sigma, computes buffered Copernicus terrain/HAND, and optionally
  obtains post-event S2. Cached mode avoids satellite requests; full uses SNAP.
- P2 `ml/` builds seven channels, applies B0 or the released U-Net with checkpoint
  normalization/calibration, and `geo/` produces statistical disturbance, gated
  classes/flags, and hazard polygons. Model-v1 holds slope at its training mean.
- P3 `data/osm.py` fetches historic OSM; `geo/settlements/exposure/network/flowpath`
  derives places, exposure, noded road multigraphs and A/B/C status layers.
- Frozen contracts define every file, grid, dtype and summary. Results is the single
  statistical source for product views. Stage functions accept RunContext and do
  not call each other. The current pipeline is a stub; CLI/report/app/E4 are absent.
- `eval/` contains Kuro and access evaluation; `docs/results/` has measured E1/E2/E3,
  E3c/E5/E8. E4/E6 real-run evidence remains open. The supplied screenshot agrees
  with the P4 product/integrator responsibilities in the repository plan.

Detailed task execution and feature branches: [P4_WORKFLOW.md](P4_WORKFLOW.md).
