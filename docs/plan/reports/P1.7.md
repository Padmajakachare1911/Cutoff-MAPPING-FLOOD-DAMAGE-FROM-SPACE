# P1.7 — Full (SNAP) backend

## What was built
- `graphs/s1_cutoff.xml`: a copy of Kuro Siwo's `configs/grd_preprocessing.xml`, fetched from
  `raw.githubusercontent.com/Orion-AI-Lab/KuroSiwo/main/` on 2026-10-12. The header comment cites it.
  It has exactly the plan's four changes; `diff` against the original shows only these lines:
  1. `Subset.geoRegion = ${geoRegion}` (the grid's WGS84 bounds + 1 km), still the node right after Apply-Orbit-File;
  2. the `Land-Sea-Mask` node is removed and Calibration reads `Remove-GRD-Border-Noise`;
  3. `Terrain-Correction`: `demName = Copernicus 30m Global DEM`, `mapProjection = ${mapProjection}`
     (`EPSG:<grid epsg>`), `pixelSpacingInMeter = 10.0` (unchanged), `saveLocalIncidenceAngle = true`;
  4. Speckle-Filter unchanged from Kuro Siwo (Lee Sigma, 7x7, 3x3, 0.9). Calibration is still σ⁰ linear
     (`outputImageScaleInDb=false`).

  Also filled in: `${input}` / `${output}` in Read/Write, and `Terrain-Correction.sourceBands = Sigma0_VV,Sigma0_VH`.
  The last one is needed because the GeoTIFF writer stores no band names; with it, the output band order is
  deterministic: VV, VH, localIncidenceAngle (see below).
- `src/cutoff/data/snap.py`
  - `find_gpt()`: `SNAP_GPT`, PATH, or default install folders.
  - `cdse_token()`: password grant, client `cdse-public`, `CDSE_USERNAME`/`CDSE_PASSWORD`.
  - `download_product()`: streams `https://download.dataspace.copernicus.eu/odata/v1/Products(<uuid>)/$value` with a
    Bearer token; the uuid comes from the STAC item.
  - `gpt_command()`.
  - `snap_to_grid()`: bilinear reprojection of the SNAP GeoTIFF onto the run grid; SNAP no-data 0 → NaN;
    dataMask band.
  - `fetch_s1_scene_snap()`: download → gpt → reproject. Results are cached under `cache/s1/{products,snap}/`.
  - `backend_consistency()`: the E3c statistic, median/p90 |ΔdB| over stable terrain.
- Wiring (P1.4): `ctx.mode == "full"` → `BACKENDS["snap"]`. Its scenes are marked pre-filtered, so `stage_s1`
  **skips** `lee_sigma`, and they are cached as `<grid_hash>.snap.tif`. Everything after that uses the same writer
  as P1.4.

## [U] SNAP parameter names: checked against the SNAP source, not `gpt -h`
SNAP is not installed on this machine, so `gpt Terrain-Correction -h` / `gpt Speckle-Filter -h` could not run. The
names were read from the operator source on GitHub (master, fetched 2026-10-12):

| Graph parameter | Source | Value used |
|---|---|---|
| `demName` | `senbox-org/microwave-toolbox` `RangeDopplerGeocodingOp.java` (alias `Terrain-Correction`): `private String demName = "Copernicus 30m Global DEM"` (now SNAP's default) | `Copernicus 30m Global DEM` |
| DEM name string | `senbox-org/snap-engine` `Copernicus30mElevationModelDescriptor.java`: `NAME = "Copernicus 30m Global DEM"` | same |
| `saveLocalIncidenceAngle` | `RangeDopplerGeocodingOp.java`: `private boolean saveLocalIncidenceAngle = false`; adds band `"localIncidenceAngle"` after the selected source bands | `true` |
| `mapProjection`, `pixelSpacingInMeter`, `alignToStandardGrid` | `RangeDopplerGeocodingOp.java` fields of these names | `EPSG:<epsg>`, 10.0, true (origin 0,0 → 10 m multiples, like our grid) |
| `filter`, `windowSize`, `targetWindowSizeStr`, `sigmaStr` | `SpeckleFilterOp.java` (alias `Speckle-Filter`): `LEE_SIGMA_FILTER = "Lee Sigma"`, `SIZE_7x7`, `SIZE_3x3`, `SIGMA_90_PERCENT = "0.9"` | as Kuro Siwo |
| output band names | `RangeDopplerGeocodingOp.addSelectedBands`: target names `Sigma0_<POL>`, in `sourceBands` order, then `localIncidenceAngle` | — |

This resolves O4, from source. Still to do: confirm against the installed version once SNAP is installed. That is now one
command (added 2026-10-13): `python -m cutoff.data.snap --check-gpt`. It runs `gpt <op> -h` for every graph operator and
lists any parameter the installed SNAP does not know (exit 0 = all known). See `P1_UPDATES_LOG.md` U3.

## Blockers (user action)
1. Install ESA SNAP (≥ 10, includes the microwave toolbox), or set `SNAP_GPT`.
2. `CDSE_USERNAME` / `CDSE_PASSWORD` in `.env`, for the OData download (~1.2 GB per GRD zip).

Then: `python -m pytest tests/test_p1_snap.py -m "network and slow" -rs`. SNAP takes about 10–25 min per scene (D1).
