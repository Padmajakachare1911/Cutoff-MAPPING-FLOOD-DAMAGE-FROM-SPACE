# P4.1 - pipeline and CLI

Implemented contract-order orchestration, timestamp parsing, dependency-complete
stage subsets, output validation, sampled process/child peak RSS, stage timings,
JSON progress logging, Results assembly, default limitations and optional flowpath.
Fresh run IDs never overwrite previous outputs. Input-only subsets write summaries
without fabricating a hazard report. Core errors write error.json and propagate.
S2 errors remove partial optional rasters and continue. P3 failures produce partial
hazard results and skip subsequent P3 stages. Snapshot validation precedes IO.

CLI delegates training and Kuro evaluation to P2; maps the planned checkpoint/strata
arguments to the actual evaluator. `.env` assignments are loaded without executing
them or overriding environment variables. Pair errors preserve their message and
exit 2. Other request errors exit 2; runtime errors exit 1.

OSM is called with a snapshot/settings-specific cache root, containing issue #25
without editing P3. Undated legacy caches are deliberately not reused.
